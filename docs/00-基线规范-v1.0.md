# 多Agent主控集群 · 基线规范 v1.0（开发约束基线）

> 本文件是平台研发的唯一需求基线。Codex 开发必须严格遵守，不得自行变更。

## 1. 体系定位

通用 Master-Worker 多智能体任务调度与审计框架，业务无关。

- **Master**：唯一调度、校验、收口、审计中枢
- **Worker（dsh / workbuddy / codex）**：纯被动执行单元，无调度权、彼此禁止直连

## 2. 平台层职责边界（最重要）

平台 = 基础设施层，**只做以下六件事**：

1. 消息总线：可靠收发 v1.0 JSON 报文，路由 Master ↔ Worker
2. 任务队列、超时管理、Worker 注册与心跳、熔断标记、全局 pause/resume
3. 持久化：台账数据库（对齐两张表结构） + 原始报文归档
4. 接入层：REST API + 极简 Web 面板（发起需求、查看流水线、高危审批、运维指令）
5. 可观测：基于 trace_id 的链路查询、基础指标
6. 平台账号与操作权限（与 Agent 内部高危审批是两套机制）

平台**绝对不实现**：

- ❌ DAG 拆解（属于 Master Agent）
- ❌ Schema 校验、验收项判定（属于 Master Agent）
- ❌ 业务逻辑、业务字段语义解释
- ❌ 任何"替 Master 做决策"的行为

## 3. 通信协议 v1.0

### 3.1 公共必带字段

```json
{
  "trace_id": "string",
  "task_id": "string",
  "msg_type": "string",
  "sender": "master | dsh | workbuddy | codex | user",
  "timestamp": "ISO8601",
  "version": "v1.0"
}
```

### 3.2 msg_type 固定枚举（8 种，不得增删改语义）

| msg_type | 方向 | 说明 |
| --- | --- | --- |
| task_dispatch | Master → Worker | 下发任务 |
| task_heartbeat | Worker → Master | 长任务进度上报（可选） |
| task_return | Worker → Master | 返回结果 |
| task_reject | Master → Worker | 驳回重跑，附校验意见 |
| task_abort | Master → Worker | 终止任务 |
| human_confirm_req | Master → User | 高危审批请求 |
| human_confirm_resp | User → Master | 审批回复 |
| task_summary | Master → User | 流水线汇总报告 |

payload 内业务字段（task_goal / input / output_schema / acceptance_criteria）随任务变化，平台只做透传存储，不解析不校验其内容。

## 4. 任务 7 种状态机

1. 待拆解
2. 待调度下发（等待依赖就绪 / 等待人工审批）
3. 执行中
4. 待验收
5. 验收通过（不可回退）
6. 验收驳回（可重试回到执行中）
7. 执行失败（阻塞下游，仅可手动 retry）

约束：

- 验收通过不可回退
- 执行失败默认阻塞下游分支
- 高危任务下发后停在【待调度下发】，收到 approve 才进入【执行中】
- 高危任务重试必须再次审批

## 5. 审计台账（追加写入，禁止覆盖/删除）

### pipeline_ledger（一条 trace_id 一行）

```text
trace_id: string
original_demand: string
start_time: ISO8601
end_time: ISO8601 | null
overall_status: pending | running | success | aborted | failed
archive_path: string | null
pause_flag: boolean
```

### task_ledger（一条 task_id 一行）

```text
trace_id: string
task_id: string
target_worker: string
dispatch_time: ISO8601 | null
return_time: ISO8601 | null
status: string
max_retry: int
remaining_retry: int
is_high_risk: boolean
reject_reason: string | null
abort_reason: string | null
log_ref: string | null
depends_on: array[string]
```

## 6. 运维控制指令（用户 → Master，固定前缀 `master:`）

```text
master: query trace_id=<id>
master: query task_id=<id>
master: abort trace_id=<id>
master: abort task_id=<id>
master: retry task_id=<id>
master: list pipeline [status=success|aborted|failed]
master: archive trace_id=<id>
master: pause
master: resume
```

平台需提供与上述语义对齐的 REST 接口，指令文本解析由 Master 负责，平台只暴露能力端点。

## 7. 异常机制

- 自动重试按 max_retry 计数，高危任务不自动重试
- Worker 连续超时/失败 → 熔断该 Worker，暂停下发新任务
- 未通过验收结果不进入正式归档
- pause 不中断执行中任务，只拦截新调度
- 归档失败视为流水线未闭环

## 8. 技术栈（MVP）

- 后端：Python 3.11 + FastAPI
- ORM：SQLAlchemy 2.x
- 数据库：SQLite（MVP），模型设计需兼容 PostgreSQL 迁移
- 队列：MVP 阶段使用进程内 asyncio 队列 + 数据库状态表，接口抽象成 `MessageBus`，后续可替换 Redis
- 前端：Vue3 + Element Plus（极简）
- 部署：docker-compose
