# 04 · 协议 v1.0

## 一、通用必带 6 字段

每条报文必须带，缺一即 422：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `trace_id` | string | 1..64 字符，一条需求一个 |
| `task_id` | string | **必填**，1..64 字符（已否决改 Optional） |
| `msg_type` | string | 必须属于 8 种白名单 |
| `sender` | string | 必须属于 5 值：master / dsh / workbuddy / codex / user |
| `timestamp` | string(ISO) | **必须是带时区的 aware 时间**；naive 时间抛 422 |
| `version` | string | 固定 `v1.0` |
| `payload` | object | 按 msg_type 自定，可为空对象 |

## 二、8 种 msg_type

| msg_type | 谁发 | 干什么 | 平台动作 |
| --- | --- | --- | --- |
| `task_dispatch` | master | 下发任务 | 过三道闸门 → 任务转「执行中」，记 dispatch_time |
| `task_heartbeat` | worker | 报活 | 只记心跳时间，不改状态 |
| `task_return` | worker | 交产出 | 任务转「待验收」 |
| `task_reject` | worker | 报做不了 | 任务转「验收驳回」，记 reject_reason |
| `task_abort` | master/worker | 中止 | 任务转「执行失败」，记 abort_reason |
| `human_confirm_req` | master | 请求人工确认 | 只归档留痕，平台不决策 |
| `human_confirm_resp` | user | 人工答复 | 只归档留痕 |
| `task_summary` | master | 阶段总结 | 只归档留痕 |

## 三、幂等键

`(trace_id, task_id, msg_type, timestamp)` 唯一。
同一条报文重投 → 返回**同一个** `archive_id`，不重复写归档、不重复推进状态。
> 实现顺序很关键：**必须先判幂等，再做状态校验**。反过来会导致"重复投递先被状态机拒成 409"——这是 Batch2 踩过的坑。

## 四、状态码约定

| 码 | 含义 | 客户端该做什么 |
| --- | --- | --- |
| 202 | 已受理（异步处理成功） | 继续 |
| 400 | 未知 msg_type / 未知指令 | 改请求，别重试 |
| 401 | 缺少或错误的 `X-API-Token` | 补令牌 |
| 404 | 引用的任务或流水线不存在 | 别重试 |
| 409 | 当前状态不接受该报文（含闸门拒绝、**执行方越权**、非 Master 派发） | 别重试，按 detail 处理 |
| 422 | 字段或 payload 校验失败（含 naive timestamp） | 改报文 |
| 503 | 总线背压 / 处理超时（报文**未被接收**） | **可重投**，看 `Retry-After` |
| 500 | 台账写入失败 | 排查，别盲目重投 |

> 503 与 409 的区别必须记住：503 是"没收下"，可以重投；409 是"收下了但状态不允许"，重投仍是 409。
>
> 重放（同 sender + payload、换 timestamp 重发）不算 409：平台按幂等处理返回 **202 + `status_changed=false` + note「重放拦截」**，不推进状态、不重复扣次数。
>
> **心跳是例外（Batch12 修正）**：`task_heartbeat` 是周期性报文，一个长任务的每条心跳内容往往完全一样。若按"内容一致"当重放拦掉，台账里的 `last_heartbeat_time` 会永远停在第一条，"还在干活"的证据就丢了。因此心跳只受幂等键（`trace_id+task_id+msg_type+timestamp`）约束：**换时间戳的重复心跳照常受理并刷新心跳时间**，同时间戳的才按幂等忽略。

## 五、报文体示例

```json
{
  "trace_id": "demo-trace-001",
  "task_id": "demo-task-001",
  "msg_type": "task_dispatch",
  "sender": "master",
  "timestamp": "2026-11-19T08:00:00+00:00",
  "version": "v1.0",
  "payload": {
    "target_worker": "workbuddy",
    "task_goal": "示例：平台自检任务",
    "acceptance_criteria": ["产出可读", "无删除操作"],
    "depends_on": []
  }
}
```

## 六、字段长度与校验（实现口径）

| 项 | 规则 |
| --- | --- |
| `trace_id` / `task_id` | 1..64；超长 → 422 |
| `status` 过滤参数 | 只接受白名单值；非法 → 422 |
| `page` | 从 1 起；<1 → 422 |
| `size` | 默认 20，上限 100；越界 → 422（**不静默截断**） |
| `format` | `json` / `csv`，其他 → 422 |

## 七、改协议的规矩

见 [12-版本变更规范](12-版本变更规范.md)。一句话：**加字段可以兼容，改语义必须升版本号（v1.1）并同步改状态机与验收脚本。**
