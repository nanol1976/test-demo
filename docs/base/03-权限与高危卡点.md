# 03 · 权限与高危卡点

## 权限矩阵

| 动作 | Master | Worker | 平台 | 人 |
| --- | --- | --- | --- | --- |
| 拆解需求 / 定验收标准 | ✅ 唯一 | ❌ | ❌ | 可提需求 |
| 派发任务（task_dispatch） | ✅ | ❌ | 只做闸门校验 | ❌ |
| 领活执行 | ❌ | ✅ 自己的任务 | ❌ | ❌ |
| 心跳 / 回传 / 驳回 | ❌ | ✅ 只能是自己名下的任务（平台强校验，越权 409） | 记录 | ❌ |
| 中止（task_abort） | ✅ 可叫停任何任务（Batch10 明确） | ✅ 只能中止自己的任务 | 记录 | ❌ |
| 改任务状态 | 通过报文 | 通过报文 | 只做状态机合法迁移 | ❌ |
| 判验收通过/驳回 | ✅ 唯一 | ❌ | ❌ | 可代判（人确认时） |
| 高危审批决策 | ❌ 需上报 | ❌ | ❌ 只留痕 | ✅ 唯一 |
| 暂停 / 恢复 / 复位熔断 | 可申请 | ❌ | 执行 | ✅ 可下令 |
| 删台账 | ❌ | ❌ | ❌ | ❌ 谁都不行 |

**三条不可让渡**：
1. 验收判定权只能在 Master 或人手上，平台不判。
2. 高危决策权只能在人手上，平台只记 `human_confirm_req` / `human_confirm_resp` 两条报文。
3. 删除权不存在——任何人任何层都不能删台账。

## 高危动作清单（必须人工确认后才继续）

| 高危动作 | 判定标准 | 平台动作 |
| --- | --- | --- |
| 删除/覆盖已有产出 | 影响已有交付物 | 只留痕，等 `human_confirm_resp` |
| 对外发送（邮件/消息/发布） | 出系统边界 | 只留痕，等确认 |
| 改共享配置 / 权限 | 影响他人 | 只留痕，等确认 |
| 大额/不可逆操作 | 无法回滚 | 只留痕，等确认 |
| 覆盖生产数据 | 影响线上 | 只留痕，等确认 |

平台对高危任务只做一件事：**给任务打 `is_high_risk=True` 标记，并把 `human_confirm_req` 落归档**。是否放行由人决定，平台不代替决策。

## 卡点实现位置

| 卡点 | 实现 | 失败表现 |
| --- | --- | --- |
| 暂停闸门 | `dispatch._require_dispatch_gate` | 409「处于暂停状态，需先 resume」 |
| 熔断闸门 | `breaker.is_open` | 409「已熔断（连续失败任务数 N ≥ 阈值 M）」 |
| 依赖闸门 | `depends_on` 校验 | 409「依赖未满足 ['t-x(执行中)']」 |
| trace 归属 | `_require_same_trace` | 409「任务不属于该 trace」 |
| 鉴权 | `security.require_token` | 401「缺少或错误的 X-API-Token」 |
| 状态机 | `IllegalTransitionError` | 409，且不落状态 |
| 执行方归属 | `dispatch._require_owner` | 409「task_heartbeat 越权：任务 X 归属 Y，报文来自 Z」，且不落归档 |
| 派发权限 | `handle_task_dispatch` 首行 | 非 Master 派发 → 409，连流水线都不建 |
| 重放 | `dispatch._find_replay`（sender + payload 指纹） | 换 timestamp 重放同一条报文 → 202 幂等忽略，不推进状态、不扣次数、不增归档 |

## 越权的典型表现（发现即视为缺陷）

- Worker 报文里改了不属于自己的 task_id → 应 404/409
- 平台代码里出现业务词（"订单""持仓""回测"）→ 违反业务无关原则
- 任何 `.delete()` / `DROP TABLE` / 覆盖写 → 违反台账铁律
- 平台代替 Master 判"合格/不合格" → 越权
