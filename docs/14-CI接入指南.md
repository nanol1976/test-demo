# 14 · CI 接入指南

本平台的 CI 门禁不依赖任何云服务、不依赖私有镜像：`scripts/ci.py` 就是全部规则，本地能跑、CI 也能跑。这份文档说明**门禁查什么**、**怎么接到仓库**、**接的过程中会踩什么坑**。

> 当前状态：仓库只有本地 `master`，`git remote -v` 为空。**没有远端、没有凭据，因此尚未真正推送。** 下文是"推送就绪"的操作手册，拿到仓库地址后按第二节执行即可。

## 一、门禁查什么

`python scripts/ci.py` 分三段，任一段失败即整体 exit 1：

| 段 | 内容 | 关键点 |
| --- | --- | --- |
| 1 静态红线 | 全部 `.py` 可编译；业务词 0 命中；台账无删除动作；接口面 9 个且只有 GET/POST；协议枚举/CHECK/幂等约束在位；前端零 CDN、有自动刷新、无 `setInterval`；查询契约（`q`、排序白名单、非法排序抛错）；前端契约（搜索框/排序/行差量渲染）；JS 语法 | 只查 `app/` 与 `migrations/`；`docs/base` 里出现业务词是**刻意的边界示例**，不参与扫描 |
| 2 迁移三段式 | 空库 `--check` **必须不通过** → `upgrade` 成功 → `--check` 通过 → 再 upgrade 幂等 | 第一段是在验"预检真的会失败"，不是永远返回 0 |
| 3 全量测试 | `scripts/run_all.py --no-smoke` | 六段验收脚本逐段 `check()` |

`--static-only` 只跑第 1 段，适合提交前本地快跑（秒级）。

两个"温和"设计：

- **node 可选**：本机没有 node 时，JS 语法门禁打印 `[PASS] JS 语法（跳过：本机没有 node）` 并留痕，不判失败。CI 镜像里装了 node 就会真跑。
- **不联网**：门禁只用 SQLite 临时库，不访问外网、不拉依赖。

## 二、接到仓库（三种常见托管）

### 2.1 GitHub Actions

仓库里已有 `.github/workflows/ci.yml`，推送后**自动生效**，无需在网页上点选。

```bash
git add .gitattributes .github scripts docs
git commit -m "chore: CI 接入"
git remote add origin git@github.com:<账号>/<仓库>.git
git push -u origin master
```

workflow 关键点（已在文件里）：

- 触发：`push` 到 `master`、对 `master` 的 `pull_request`、手动 `workflow_dispatch`
- 运行时：`ubuntu-latest` + `actions/setup-python@v5`（3.11）
- 步骤：装 `requirements.txt` → `python scripts/ci.py`
- **不需要 secrets**：门禁不调用任何外部 API

### 2.2 Gitee Go / Gitee 流水线

Gitee 不认 `.github/workflows`，需要一份 `.workflow/` 或在网页里配"流水线"。最省事的做法是**只配一条命令**：

```yaml
# .gitee/pipeline.yml（按 Gitee Go 模板改写）
stages:
  - stage: ci
    jobs:
      - job: gate
        steps:
          - step: setup_python
            python: 3.11
          - step: shell
            run: |
              python -m pip install -r requirements.txt
              python scripts/ci.py
```

Gitee 的 YAML 结构各家模板略有差异，**不用照抄**，核心只有一句 `python scripts/ci.py`。

### 2.3 内网 GitLab CI

加 `.gitlab-ci.yml`：

```yaml
stages: [test]

ci:
  stage: test
  image: python:3.11-slim
  script:
    - pip install --no-cache-dir -r requirements.txt
    - python scripts/ci.py
  cache:
    paths: [".pip-cache"]
```

内网镜像若限流，把 `pip install` 换成内网源（`-i http://内网源/simple`）。

## 三、本地提交前建议

```bash
python scripts/ci.py --static-only   # 秒级，先挡明显问题
python scripts/ci.py                 # 完整三段，约 3~5 分钟
```

想更省事可以挂 pre-commit hook（本平台不内置，避免强加依赖）：

```bash
# .git/hooks/pre-commit
#!/bin/sh
python scripts/ci.py --static-only || exit 1
```

## 四、一定会踩的坑

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| 换行被 Windows 改掉 | `deploy/run.sh` 在 Linux/CI 上报 `bad interpreter` 或 `\r` 错误 | 仓库根必须有 `.gitattributes`（本平台已加：默认 LF，`.ps1` 保持 CRLF） |
| PowerShell 脚本中文乱码 | `run.ps1` 报"缺少右 }" | 必须存成 **UTF-8 带 BOM**；CI 不跑 `.ps1`，只在 Windows 本机相关 |
| SQLite 文件被占用 | Windows 上 `WinError 32` | 验收脚本清理段已改为 `dispose()` + 容错删除 |
| 测试之间污染 | 后跑的脚本读到前一个脚本的库 | 每个 verify 脚本自己设独立 `DATABASE_URL` / `ARCHIVE_ROOT`，跑前删除旧库 |
| 迁移门禁第一段"没失败" | 空库 `--check` 返回 0 → 门禁失败 | 说明预检逻辑坏了，不是用例错 |
