# Batch29 任务规格：优雅停止（stop flag）

> 执行者：Codex。验收者：主 Agent。本文件即验收依据，逐条对照实现。
> 仓库根：`C:\Users\longf\codex-workspace\master-worker-platform`（Windows，pwsh 7）

## 背景（为什么做）

现在停平台/worker 只有硬杀：Windows 上 `Stop-Process` 与计划任务「结束任务」都落到
`TerminateProcess`，执行到一半的任务直接被判失败，日志里连 `stopping` 都留不下。
目标：给一条**自愿停**的通道——平台落一个停止标记，worker 轮询到之后不再领新活、
等在飞任务收尾（已有 `grace_seconds` 机制，默认 30 秒）再退出。

## 硬约束（违反即不验收）

1. **不新增接口路径**。接口面仍 11 个，复用 `POST /api/commands` 增一个指令取值。
2. **不改前端**（`app/static/*` 一个字节都不要动）。
3. **不碰** `.env`、`data/mvp.db`、计划任务、任何进程（不许 `Stop-Process`、不许 `taskkill`、不许 `pkill`）。
4. **不 commit、不 push**，只留工作区改动。
5. 注释用中文；Python 3.11；不改既有鉴权语义（三条写接口仍由 `require_write` 守，只读口令必须 403）。
6. 数据库结构**不变**（不加表、不加列）——审计复用现有 `worker_quota_audit` 表。

## 要实现的四件事

### 1) 新增 `app/core/stopflag.py`

提供停止标记的读写，全局单一实现：

- 常量 `STOP_FILE_NAME = "STOP"`
- `stop_file_path() -> str`：先读环境变量 `MWP_STOP_FILE`；没有则返回 `data/STOP`（相对当前工作目录）。
  **必须有环境变量覆盖**——验收脚本要在临时目录里跑，绝不允许往真实 `data/` 写标记把生产 worker 停掉。
- `request_stop(reason: str = "") -> str`：写文件（UTF-8），内容为一行 `ISO 时间 + 空格 + reason`，返回写入的路径。
- `clear_stop() -> bool`：删文件，删掉了返回 True，本来不存在返回 False。
- `is_stopped() -> bool`：文件在不在。
- 写文件用 `os.replace(tmp, path)` 原子落盘（同 worker 里 `_write_status` 的做法），并 `os.makedirs(..., exist_ok=True)`。

### 2) `app/api/routes_commands.py` 增指令 `master:stop`

- `ALLOWED_COMMANDS` 加 `"master:stop"`。
- `CommandResult` 加字段 `stopping: bool = False`。
- `master:stop`：
  - **不需要 `trace_id`**（与 `master:worker-limit` 一样走独立分支，别走进「必须有 trace_id」那段）。
  - 调 `request_stop(payload.reason or "")`，落一行审计（`worker_id="master"`、`instance_id="data"`、
    `command="master:stop"`、`reason`、`operator` 传 `X-Operator`），`db.commit()`，返回 `stopping=True`。
  - 日志一行 `logger.info`。
- `master:resume`：在原有「恢复该 trace + 复位熔断」之外，**再调 `clear_stop()`**（幂等：本来没有也不报错），
  这样一条 resume 就能把「停机」和「暂停派发」一起恢复。返回结果里 `stopping=False`。
- 文档字符串/接口 description 里补上 `master:stop` 的说明。

### 3) `worker/agent_worker.py` 认这个标记

- 新增纯函数（放模块级，方便验收脚本直接 import 测试）：

```python
def should_stop(stop_file: str) -> bool:
    """停止标记存在即该收尾退出。路径为空返回 False。"""
```

- `AgentWorker.run()` 里新增参数 `stop_file: str = ""`，主循环**每轮拉活之前**检查：
  `should_stop(self.stop_file)` 为真 → `log("stop_flag_seen", stop_file=...)` 后调 `self.stop()`。
  复用已有的 `stopping` 分支（`report("stopping")` + `_drain(grace_seconds)` + `return 0`），**不要**另写一套。
- 命令行加 `--stop-file`，默认值取 `os.environ.get("MWP_STOP_FILE", "data/STOP")`，透传到 `run()`。
- **不要自己删标记文件**：标记由平台的 `master:resume` 清，worker 只读不写。

### 4) 验收脚本 `scripts/verify_b29.py`

照 `scripts/verify_b28.py` 的写法（同样的 import 引导、`[PASS]/[FAIL]` 输出、退出码）。至少覆盖：

1. 临时目录（`tempfile.mkdtemp()` + `os.environ["MWP_STOP_FILE"]=tmp/STOP`）里，`is_stopped()` 初始 False。
2. 全权口令 `POST /api/commands {"command":"master:stop","reason":"verify"}` → **200** 且 `stopping=true`，标记文件已生成、内容含日期串。
3. 审计多出一行 `command="master:stop"`（用现有 `/api/audit` 或直接查库）。
4. 只读口令发同一条 → **403**（不是 401，也不是 422）。
5. `{"command":"master:stop"}` 不带 trace_id 也能成功（第 2 条已覆盖，断言别被 422 打回）。
6. 全权 `master:resume` + 一条存在的 trace_id → 200，且标记文件被删除。
7. `should_stop(path)`：不存在的路径 False；touch 出文件后 True。
8. 静态检查：`ALLOWED_COMMANDS` 含 `master:stop`；`app/core/stopflag.py` 里同时有 `STOP_FILE_NAME`、`MWP_STOP_FILE`、`os.replace`；worker 里有 `def should_stop`、`stop_file`、`--stop-file`、`stop_flag_seen`。

**注意**：脚本必须在临时目录跑，收尾删掉临时标记；过程中**不许**用真实 `data/STOP`。
