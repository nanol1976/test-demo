# B30-A 看板「优雅停止」按钮（实施后补记）

> 说明：本文件为实施完成后补写的规格与验收记录（Batch30-A 的实际实现由主控手工完成，
> 派给 Windows Codex 的两轮均因越界重写被回滚，详见文末「事故」）。留档目的是让后续批次
> 有据可查：为什么按钮这样做、只读态为什么必须一起置灰。

## 目标
看板提供「优雅停止」入口，等价于 `POST /api/commands {"command":"master:stop"}`：
平台落 `data/STOP` 标记 → worker 收完在飞任务后自行退出（Batch29 已实现服务端语义）。
前端只是入口，服务端仍是唯一闸门。

## 允许改动的白名单
`app/static/index.html`、`app/static/app.js`、`app/static/style.css`、`run/probe_mode.js`（桩）

## 实现要点
- `index.html`：在「复位熔断」之后新增
  `<button id="btnStop" class="btn-warn" title="落停止标记…">优雅停止</button>`，仍位于流水线详情面板的工具条内。
- `app.js`：`WRITE_BTNS` 增 `"btnStop"`（只读态统一置灰）；新增 `stopMaster()`：
  只读守卫 → `window.confirm` 二次确认 → POST `{command:"master:stop", reason:"从看板下发"}`
  → 成功提示「恢复请点『恢复派发』」→ `loadWorkers()` 刷新；`bind()` 内绑定点击。
- `style.css`：`button.btn-warn { border-color: var(--warn); color: var(--warn) }` + hover（描边不填底，符合台账语言）。
- `run/probe_mode.js`：桩从 12 项扩到 14 项，新增「只读态 btnStop.disabled===true」「全权态 false」。

## 门禁红线（scripts/ci.py）
1. `index.html` 有 `id="btnStop"` 且含「优雅停止」
2. `WRITE_BTNS` 含 `btnStop`
3. 有 `stopMaster` 且含 `"master:stop"` 且在 `bind()` 内绑定
4. `style.css` 有 `button.btn-warn`
